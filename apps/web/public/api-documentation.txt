Post Engineer API
================================================================================

Base URL:        https://post-engineer.com
Development URL: http://localhost:3434
OpenAPI spec:    https://post-engineer.com/openapi.json
MCP server:      npx -y post-engineer-mcp@latest (env POST_ENGINEER_API_KEY)

The OpenAPI spec lists every endpoint below. It is generated from the MCP
parity mapping (apps/mcp/src/__tests__/parity-endpoint-tools.json) by
`node apps/web/scripts/generate-openapi.mjs`, with request and response
schemas from apps/web/scripts/openapi-schemas.mjs. Some nested items (social
accounts, metrics rows, generation lists) are typed as free-form objects.

================================================================================
AUTHENTICATION
================================================================================

Create an API key in the dashboard (https://post-engineer.com/recipes) or
through POST /api/api-keys (web session only). Keys start with `pe_live_`
and are shown once.

Send the key on every request, either way:

  Authorization: Bearer pe_live_xxxxxxxx
  X-API-Key: pe_live_xxxxxxxx

A key can be limited to specific personas. A missing key returns 401
"Authentication required."; an invalid key returns 401 "Invalid API key.".

================================================================================
RESPONSES AND ERRORS
================================================================================

- JSON bodies. Failures carry success:false and an error message.
- Most routes return a flat { "success", ... } payload. Only the two engine
  proxies, GET /api/persona/video-status/{taskId} and
  DELETE /api/persona/video-task/{taskId}, return the engine envelope
  { "status", "message", "body" }: the payload is `body`, never `data`.
- 400 invalid, over-length or conflicting input (nothing is truncated or
  coerced silently). POST /api/videos/generate-and-schedule lists every
  problem in one response: `code`, `error` and `field` describe the first
  one, and `errors` (an array of { code, message, field }) holds at most 20 of them. 401 bad key. 402 not enough tokens. 404 unknown id.
  409 conflict (e.g. the persona already has an active schedule). 410 gone:
  terminal, stop polling. 429 rate limited: retry with backoff. 5xx
  transient: retry with backoff. Each operation's statuses are in the spec.
- Upload, destructive and fan-out routes are rate limited per caller.

================================================================================
VIDEOS (cost prepaid tokens: faceless 1, ok 2, very_good 3)
================================================================================

Check the balance first: GET /api/billing/tokens.

1. POST /api/videos/validate-script   mechanical validation, spends no tokens
2. POST /api/videos/score-draft       mechanical score + publish check, no tokens
3. POST /api/videos/generate-and-schedule
   One call generates the video, schedules it and auto-publishes it. There
   are no orphan videos. Script is segments: hook first, body, CTA last,
   60-200 words total. Slot is 3h to 30d ahead, or mode "asap".
4. GET  /api/persona/video-status/{taskId}   task state
   state: -1 failed, 1 complete, 3 queued, 4 processing. Only -1 and 1 are
   terminal. HTTP 200 does not mean the job is alive: read `state`.
   410 Gone is terminal too (the engine lost the task): stop polling and
   read GET /api/schedule/slots/{slotId} to see if the video was delivered
   or failed and refunded.
5. DELETE /api/persona/video-task/{taskId}   cancel a task

Jobs stuck for several days are refunded automatically.

================================================================================
SOCIAL ACCOUNTS
================================================================================

Supported: YouTube, Instagram, LinkedIn, Threads, Facebook Pages, Bluesky,
3Speak, Rumble. Connect via POST /api/account/connect-url (returns an https
auth_url to open in a browser), POST /api/bluesky-connect (app password),
POST /api/threespeak-connect (Hive posting key) or POST /api/rumble-connect
(access token issued by emailing bd@rumble.com). Then map accounts to a
persona with PUT /api/persona/publishing-accounts.

================================================================================
MARKETPLACES (RapidAPI, Apify, MCP Registry)
================================================================================

The same API key works everywhere; tokens are always billed by Post Engineer.

- RapidAPI: send your Post Engineer key in Authorization: Bearer pe_live_...
  next to the X-RapidAPI-Key header. RapidAPI forwards it; without it the API
  returns 401.
- Apify: the "Post Engineer video" Actor takes the key as a secret input and
  calls POST /api/videos/generate-and-schedule for you (source:
  integrations/apify in the repository).
- MCP Registry: io.github.Ryan-Carloso/post-engineer (npm post-engineer-mcp),
  configured with POST_ENGINEER_API_KEY.
