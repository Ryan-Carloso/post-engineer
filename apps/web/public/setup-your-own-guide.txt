================================================================================
ARCHITECTURE (v3.0.0) — WHAT CHANGED
================================================================================

The old token.json local-file storage has been REMOVED.

Current model:
- OAuth tokens are encrypted (AES-256-GCM) and stored in Supabase
  (table `social_accounts`, column `encrypted_tokens`)
- Web users log in via Supabase (GitHub OAuth)
- API clients authenticate with App API Keys (post-engineer_...)
- Token auto-refresh happens server-side; refreshed tokens are re-encrypted
  and persisted back to Supabase automatically

DO NOT create, read, or write token.json. It does not exist anymore.

UPLOAD (Main Functionality — requires API key)
----------------------------------------------

POST /api/upload
Content-Type: multipart/form-data
Authorization: Bearer post-engineer_...

REQUIRED FIELDS (no defaults, no fallbacks):
- video: File (max 2GB, video/*)
- title: String (non-empty, trimmed)
- description: String (non-empty, trimmed)
- tags: String (comma-separated, min 1 tag)
- privacyStatus: Enum ("public"|"private"|"unlisted")
- accountId: String (channelId of a connected YouTube account)

ERROR TYPES AGENTS MUST HANDLE:
-------------------------------

ValidationError (400):
- Missing required fields
- Invalid field values
- File validation failures
→ Action: Validate input before retry

AuthError (401):
- Missing/invalid API key
- Account not found for the API key owner
- Token refresh failures
→ Action: Check the Bearer key; restart OAuth flow via /api/google-oauth/start

TimeoutError (408):
- Upload exceeded 30 minutes
→ Action: Retry with smaller file or better connection

UploadError (500):
- Network issues during upload
- API communication failures
→ Action: Retry with better network conditions

YouTubeApiError (500):
- YouTube Data API errors
→ Action: Check YouTube API status, permissions

NetworkError (500):
- Connection failures
→ Action: Retry with better network

AI AGENT ERROR HANDLING STRATEGY:
----------------------------------

1. ALWAYS check response.success
2. If false, use logId for debugging
3. Implement specific handling per errorType
4. Follow suggestions array for recovery
5. Log all errors with logId for tracking

- Must be exactly: "public", "private", or "unlisted"
- NO default value
- Error if fails: ValidationError("Status de privacidade inválido")

ACCOUNT ID VALIDATION:
- Must be a YouTube account connected by the API key owner
- Error if fails: AuthError("Conta não encontrada...")

TOKEN MANAGEMENT - SUPABASE-BACKED (AI AGENT REQUIREMENTS)
================================================================================

There is NO local token file. Never implement file-based token storage.

Current implementation (server-side):
```typescript
import { getSocialAccountTokens, updateSocialAccountTokens } from '@/lib/social-accounts';
import { createSupabaseServiceClient } from '@/lib/supabase/service';
import { resolveAppApiKey } from '@/lib/app-api-key-manager';

async function getAuthenticatedClient(apiKey: string, accountId: string) {
  // 1. Resolve the API key → owner user_id
  const keyInfo = await resolveAppApiKey(apiKey);
  if (!keyInfo) throw new AuthError('API key inválida', 'invalid_api_key');

  const supabase = createSupabaseServiceClient();

  // 2. Fetch + decrypt tokens (AES-256-GCM) from Supabase
  const { tokens } = await getSocialAccountTokens(
    supabase, keyInfo.userId, 'youtube', accountId
  );

  const oauth2Client = await createOAuth2Client();
  oauth2Client.setCredentials(tokens);

  // 3. Auto-refresh if expired — refreshed tokens go back ENCRYPTED
  if (tokens.expiry_date && tokens.expiry_date < Date.now()) {
    const { credentials } = await oauth2Client.refreshAccessToken();

    const updatedTokens = {
      access_token: credentials.access_token,
      refresh_token: credentials.refresh_token || tokens.refresh_token,
      token_type: credentials.token_type || tokens.token_type || 'Bearer',
      expiry_date: credentials.expiry_date ?? undefined,
    };

    await updateSocialAccountTokens(
      supabase, keyInfo.userId, 'youtube', accountId, updatedTokens
    );
    oauth2Client.setCredentials(updatedTokens);
  }

  return oauth2Client;
}
```

Key invariants:
- encryptTokens()/decryptTokens() (lib/token-crypto.ts) — AES-256-GCM,
  key from TOKEN_ENCRYPTION_KEY env (base64, 32 bytes), no fallback
- Tokens never touch the filesystem
- Tokens are never returned to any client
- RLS policies restrict social_accounts rows to their owner

SECURITY REQUIREMENTS - AI AGENT COMPLIANCE
================================================================================

NEVER COMMIT THESE FILES (Security Risk):
- .env (contains API secrets)
- logs/ (may contain sensitive info)
- uploads/ (temporary files)

FILE PERMISSIONS (Production):
- .env: 600 (owner read/write only)
- logs/: 700 (owner read/write/execute only)

API KEY SECURITY:
- Store post-engineer_... keys in a secrets manager, never in code
- Keys are stored server-side as sha256 hashes (key_hash)
- Rotate keys via the App API Key tab if compromised

TOKEN SECURITY:
- AES-256-GCM encryption at rest in Supabase
- Never expose SUPABASE_SERVICE_ROLE_KEY to the client
- Never implement local token.json storage (removed architecture)

6. Upload with progress bar and 30-minute timeout

COMMON IMPLEMENTATION PITFALLS - AVOID THESE
================================================================================

❌ AUTH MISTAKE:
Calling /api/upload without "Authorization: Bearer post-engineer_..."
✅ CORRECT: Generate a key in the App API Key tab and send the header

❌ MISSING FIELD MISTAKE:
Omitting the accountId form field
✅ CORRECT: Every upload must target a connected account (accountId)

❌ TOKEN MISTAKE:
Writing tokens to token.json (removed architecture)
✅ CORRECT: Tokens live encrypted in Supabase; server refreshes them

❌ VALIDATION MISTAKE:
Adding fallback values for required fields
✅ CORRECT: Reject requests with missing/invalid fields

❌ ERROR HANDLING MISTAKE:
Generic error handling without logId usage
✅ CORRECT: Use logId for debugging, specific error handling

❌ SECURITY MISTAKE:
Committing sensitive files or exposing the service role key
✅ CORRECT: Add .env and logs/ to .gitignore; keep service key server-only
